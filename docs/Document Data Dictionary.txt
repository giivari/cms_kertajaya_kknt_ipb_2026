# 1. Pendahuluan

## 1.1 Tujuan Dokumen

Dokumen Data Dictionary menjelaskan definisi teknis setiap tabel dan atribut pada basis data Village Website CMS.

Dokumen ini digunakan sebagai acuan untuk:

1. Pembuatan migration Laravel.
2. Pembuatan model Eloquent.
3. Penentuan primary key dan foreign key.
4. Penentuan tipe data PostgreSQL.
5. Penentuan aturan validasi.
6. Penentuan indeks dan constraint.
7. Pembuatan resource pada Filament.
8. Pengujian struktur basis data.

---

## 1.2 Konvensi Penamaan

Konvensi yang digunakan adalah:

* Nama tabel menggunakan bentuk jamak dan `snake_case`.
* Nama kolom menggunakan `snake_case`.
* Primary key menggunakan nama `id`.
* Foreign key menggunakan pola `{nama_entitas}_id`.
* Waktu pembuatan menggunakan `created_at`.
* Waktu perubahan menggunakan `updated_at`.
* Soft delete menggunakan `deleted_at`.
* Nilai boolean menggunakan awalan `is_` atau akhiran `_enabled`.
* Nilai waktu menggunakan tipe `timestamp with time zone`.
* Data fleksibel menggunakan tipe `jsonb`.

---

## 1.3 Konvensi Tipe Data

| Tipe Logis        | PostgreSQL  | Laravel Migration |
| ----------------- | ----------- | ----------------- |
| ID utama          | bigint      | `bigIncrements()` |
| Foreign key       | bigint      | `foreignId()`     |
| Teks pendek       | varchar     | `string()`        |
| Teks panjang      | text        | `text()`          |
| Boolean           | boolean     | `boolean()`       |
| Bilangan bulat    | integer     | `integer()`       |
| Bilangan besar    | bigint      | `bigInteger()`    |
| Koordinat         | decimal     | `decimal()`       |
| Data fleksibel    | jsonb       | `jsonb()`         |
| Tanggal dan waktu | timestamptz | `timestampTz()`   |
| Soft delete       | timestamptz | `softDeletesTz()` |

## 2.2 Struktur Tabel

| Kolom               | Tipe        | Panjang | Null  | Default           | Key | Keterangan                 |
| ------------------- | ----------- | ------: | ----- | ----------------- | --- | -------------------------- |
| id                  | bigint      |       – | Tidak | Auto increment    | PK  | ID administrator           |
| name                | varchar     |     150 | Tidak | –                 | –   | Nama administrator         |
| username            | varchar     |     100 | Tidak | –                 | UQ  | Username login             |
| email               | varchar     |     255 | Ya    | null              | UQ  | Email administrator        |
| password            | varchar     |     255 | Tidak | –                 | –   | Password dalam bentuk hash |
| totp_secret         | text        |       – | Ya    | null              | –   | Secret TOTP terenkripsi    |
| totp_enabled        | boolean     |       – | Tidak | false             | –   | Status TOTP                |
| last_login_at       | timestamptz |       – | Ya    | null              | IDX | Waktu login terakhir       |

4. Akun administrator tidak dapat dihapus melalui dashboard.

6. `totp_secret` wajib dienkripsi pada tingkat aplikasi.

# 27. Strategi Full-Text Search

Pencarian publik mencakup:

* Judul, ringkasan, dan konten halaman.
* Judul, ringkasan, dan isi berita.
* Judul dan deskripsi dokumen.

Karena konten Page Builder disimpan dalam `JSONB`, sistem perlu membuat teks terindeks dari komponen yang memang dapat dicari.

Terdapat dua alternatif implementasi:

## Alternatif Awal

Mengambil konten melalui query aplikasi dan menggunakan `ILIKE`.

Cocok untuk:

* Data kecil.
* Tahap awal.
* Hosting ekonomis.

## Alternatif Lanjutan

Menambahkan kolom pencarian terdenormalisasi, misalnya:

```text
searchable_text
```

atau:

```text
search_vector
```

yang diisi dari judul, ringkasan, dan komponen halaman.

Untuk versi pertama, pendekatan `ILIKE` dapat digunakan terlebih dahulu. Full-text search PostgreSQL dapat ditambahkan ketika volume konten meningkat.

# 28. Aturan Validasi Tingkat Aplikasi

Selain constraint basis data, aplikasi wajib melakukan validasi berikut:

1. Slug dibuat dalam format URL yang aman.
2. Slug harus unik sebelum penyimpanan.
3. URL eksternal harus memiliki protokol yang diizinkan.
4. Rich text harus melalui sanitasi HTML.
5. File harus divalidasi berdasarkan MIME type.
6. Ukuran file harus mengikuti batas konfigurasi.
7. Data Page Builder harus mengikuti schema masing-masing komponen.
8. Gambar publik harus memiliki alt text atau ditandai dekoratif.
9. Koordinat harus valid.
10. Pesan narahubung harus melewati antirbot.
11. Status hanya boleh memakai nilai yang telah ditentukan.
12. Media yang masih digunakan tidak boleh dihapus permanen.
13. Admin wajib memasukkan password lama dan TOTP ketika mengganti password.
14. Data rahasia tidak boleh dimasukkan ke audit log.
15. Tautan menu harus sesuai dengan `link_type`.
