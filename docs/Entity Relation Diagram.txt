# 2. Prinsip Perancangan Basis Data

## 2.1 Single Village Installation

Setiap instalasi sistem hanya digunakan oleh satu desa.

Oleh karena itu, basis data tidak memerlukan atribut:

* `village_id`
* `tenant_id`
* `organization_id`

Identitas desa disimpan melalui tabel pengaturan website.

---

## 2.2 Single Administrator

Sistem hanya memiliki satu akun administrator utama.

Tabel administrator tetap digunakan agar sistem autentikasi dapat dikelola secara terstruktur. Namun, aplikasi tidak menyediakan fitur:

* Registrasi administrator.
* Penambahan administrator.
* Penghapusan administrator.
* Penonaktifan administrator utama.

---

## 2.3 JSON-Driven Page Builder

Page Builder menggunakan pendekatan JSON-driven.

Struktur utama Page Builder terdiri atas:

```text
Page
└── Page Section
    └── Page Component
```

Data spesifik komponen disimpan dalam kolom `content_data` bertipe `JSONB`.

Contoh komponen heading:

```json
{
  "text": "Profil Desa",
  "level": "h2",
  "alignment": "left"
}
```

Contoh komponen gambar:

```json
{
  "media_id": 15,
  "caption": "Kantor Desa",
  "alt_text": "Tampak depan Kantor Desa",
  "display_style": "rounded"
}
```

Contoh komponen statistik:

```json
{
  "items": [
    {
      "label": "Jumlah Penduduk",
      "value": "15000",
      "icon": "users"
    },
    {
      "label": "Jumlah Dusun",
      "value": "6",
      "icon": "map"
    }
  ]
}
```

Pendekatan ini dipilih karena:

1. Memungkinkan penambahan tipe komponen tanpa membuat tabel baru.
2. Mempermudah pengembangan Page Builder.
3. Mengurangi kompleksitas Entity Relationship Diagram.
4. Mendukung konfigurasi komponen yang berbeda-beda.
5. Sesuai dengan karakteristik PostgreSQL yang mendukung `JSONB`.
6. Mempermudah penggunaan ulang sistem pada desa lain.

---

## 2.4 Soft Delete dan Pengarsipan

Sistem membedakan:

### Arsip

Konten tetap tersimpan, tetapi tidak ditampilkan kepada pengunjung.

### Soft Delete

Data dianggap dihapus oleh administrator, tetapi masih dapat dipulihkan secara teknis dalam masa retensi.

### Permanent Delete

Data dihapus permanen setelah masa retensi atau melalui prosedur teknis khusus.

Untuk mencegah kehilangan data akibat kesalahan, tabel konten utama disarankan menggunakan kolom:

```text
deleted_at
```

Administrator tidak harus memperoleh menu tempat sampah pada versi pertama.

# 4. Deskripsi Entitas

## 4.1 Entitas `admins`

### Fungsi

Menyimpan akun administrator utama.

### Atribut Utama

| Atribut             | Keterangan                              |
| ------------------- | --------------------------------------- |
| id                  | Primary key                             |
| name                | Nama administrator                      |
| username            | Username untuk login                    |
| email               | Email administrator                     |
| password            | Password dalam bentuk hash              |
| totp_secret         | Secret autentikasi TOTP yang dienkripsi |
| totp_enabled        | Status aktivasi TOTP                    |
| last_login_at       | Waktu login terakhir                    |
| last_login_ip       | Alamat IP login terakhir                |
| password_changed_at | Waktu perubahan password                |
| remember_token      | Token remember session                  |
| created_at          | Waktu pembuatan                         |
| updated_at          | Waktu perubahan                         |

### Aturan

1. Tabel hanya boleh memiliki satu akun administrator aktif.
2. Username harus unik.
3. Email harus unik apabila digunakan.
4. Password tidak disimpan dalam bentuk teks biasa.
5. `totp_secret` harus dienkripsi pada tingkat aplikasi.
6. Administrator tidak dapat dihapus melalui dashboard.

* Optimasi gambar.
* Pembuatan thumbnail.
* Pemrosesan pekerjaan latar belakang.

### `failed_jobs`

Menyimpan antrean yang gagal diproses agar dapat diperiksa dan dijalankan ulang.

# 8. Aturan Integritas Data

## 8.1 Slug

Atribut `slug` harus unik pada tabel masing-masing:

* pages
* news
* gallery_albums
* documents
* locations
* news_categories
* document_categories
* location_categories

Slug menggunakan:

* Huruf kecil.
* Angka.
* Tanda hubung.
* Tanpa spasi.
* Tanpa karakter khusus yang tidak aman.

---

## 8.2 Foreign Key

Foreign key wajib diterapkan untuk menjaga konsistensi data.

Contoh:

```text
page_sections.page_id
```

harus merujuk ke:

```text
pages.id
```

---

## 8.3 Cascade Delete

Cascade delete digunakan secara terbatas.

### Dapat menggunakan cascade

* Page dihapus → section ikut dihapus.
* Section dihapus → component ikut dihapus.
* Album dihapus → album item ikut dihapus.
* Menu dihapus → menu item ikut dihapus.
* Admin dihapus secara teknis → recovery code ikut dihapus.

### Tidak menggunakan cascade langsung

* Media.
* Audit log.
* Dokumen publik.
* Berita.
* Lokasi.

Media tidak boleh terhapus otomatis apabila masih digunakan pada bagian lain.

---

## 8.4 Unique Constraint

Unique constraint diterapkan pada:

* admins.username
* admins.email
* pages.slug
* news.slug
* gallery_albums.slug
* documents.slug
* news_categories.slug
* document_categories.slug
* location_categories.slug
* locations.slug
* website_settings.setting_key

---

## 8.5 Check Constraint

Check constraint disarankan untuk:

* Nilai status.
* Latitude antara -90 dan 90.
* Longitude antara -180 dan 180.
* Position tidak bernilai negatif.
* Ukuran file tidak bernilai negatif.

# 12. Retensi Data

## Audit Log

* Log aktivitas umum: 12 bulan.
* Log keamanan: 24 bulan.
* Penghapusan dilakukan otomatis oleh sistem.

## Pesan Narahubung

* Pesan aktif disimpan selama masih diperlukan.
* Pesan arsip dapat disimpan selama 12 bulan.
* Penghapusan menyesuaikan kebijakan pengelola.

## Soft Delete

* Data dapat dipertahankan selama 30 hari sebelum penghapusan permanen.
* Penghapusan permanen dilakukan oleh scheduled task.

## Session

* Session yang kedaluwarsa dibersihkan secara berkala.

---

# 13. Pertimbangan Keamanan Basis Data

1. Kredensial database disimpan dalam environment variable.
2. File `.env` tidak disimpan di repository publik.
3. Akun database produksi memiliki hak akses minimum.
4. Query menggunakan Eloquent ORM atau parameter binding.
5. Password administrator disimpan menggunakan hashing.
6. Secret TOTP dienkripsi.
7. Recovery code disimpan menggunakan hashing.
8. Audit log tidak menyimpan password, token, atau secret.
9. Backup database harus dienkripsi atau disimpan pada lokasi yang terlindungi.
10. Pesan narahubung tidak dapat diakses guest.
11. Data sensitif tidak dimasukkan ke log.
12. File upload harus melalui validasi MIME type dan ukuran.

---

# 14. Strategi Backup

Backup mencakup:

1. Database PostgreSQL.
2. Media dan dokumen.
3. File konfigurasi deployment yang diperlukan.
4. Daftar environment variable tanpa membocorkan nilai rahasia.

Rekomendasi awal:

* Backup database mingguan.
* Backup file media mingguan.
* Backup sebelum deployment besar.
* Backup sebelum migrasi database.
* Minimal satu salinan backup disimpan di lokasi berbeda.

# 15. Kesimpulan

Rancangan basis data Village Website CMS menggunakan pendekatan relasional yang dikombinasikan dengan struktur `JSONB` untuk mendukung Page Builder yang fleksibel.

Struktur utama Page Builder terdiri atas:

```text
pages
page_sections
page_components
```

Pendekatan tersebut memungkinkan administrator menyusun halaman dengan berbagai layout dan komponen tanpa perubahan source code atau struktur database utama.

Rancangan ini mendukung:

* Satu instalasi untuk satu desa.
* Satu administrator utama.
* Pengelolaan konten tanpa coding.
* Penggunaan ulang sistem pada desa lain.
* Pengembangan komponen baru.
* Pengamanan aktivitas administrator.
* Penyimpanan media terpusat.
* Pengelolaan menu dinamis.
* Penerapan pada hosting ekonomis.
