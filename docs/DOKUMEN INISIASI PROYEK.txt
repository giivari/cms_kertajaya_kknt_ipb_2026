# Software Requirements Specification (SRS) v1.0

## Village Website CMS (Single Village Installation)

### 1. Tujuan Sistem

Village Website CMS merupakan sistem manajemen website desa yang dirancang untuk memungkinkan sebuah desa memiliki website resmi yang dapat dikelola tanpa kemampuan pemrograman.

Sistem bersifat reusable, sehingga source code yang sama dapat digunakan oleh desa lain dengan hanya mengganti identitas, konten, dan konfigurasi website.

---

# 2. Ruang Lingkup Sistem

Sistem menyediakan:

* Website publik untuk masyarakat.
* Dashboard administrasi untuk pengelolaan konten.
* Page Builder berbasis blok.
* Pengelolaan berita.
* Pengelolaan dokumen.
* Pengelolaan galeri.
* Pengelolaan pesan narahubung.
* Pengelolaan menu website.
* Pengelolaan identitas website.
* Audit log aktivitas.

Sistem tidak mencakup:

* Sistem administrasi kependudukan.
* Sistem surat menyurat otomatis.
* Sistem bantuan sosial.
* Sistem pembayaran.
* Sistem multi-desa.
* Sistem multi-admin.

---

# 3. Aktor Sistem

## Guest

Pengunjung website yang tidak perlu login.

Hak akses:

* Melihat seluruh konten publik.
* Mengunduh dokumen publik.
* Menggunakan pencarian.
* Mengirim pesan melalui narahubung.

## Admin

Pengelola website.

Hak akses:

* Login dashboard.
* Mengelola seluruh konten.
* Mengelola menu.
* Mengelola media.
* Mengelola pengaturan website.
* Melihat log aktivitas.
* Mengelola pesan narahubung.

---

# 4. Arsitektur Sistem

Model:

Single Village CMS

Setiap instalasi hanya melayani satu desa.

Satu source code dapat digunakan kembali untuk banyak desa melalui instalasi terpisah.

---

# 5. Teknologi Utama

Backend:
Laravel

Admin Panel:
Filament

Frontend:
Blade + Tailwind CSS

Database:
PostgreSQL

Map:
Leaflet + OpenStreetMap (dengan opsi integrasi Google Maps untuk embed atau navigasi)

Version Control:
Git + GitHub

Deployment Awal:
Hosting ekonomis berbasis shared hosting atau VPS ringan (misalnya Dewabiz, Niagahoster, atau layanan sejenis yang mendukung Laravel)

Reverse Proxy / Security:
Cloudflare (digunakan untuk SSL, proteksi DDoS, caching, dan optimasi performa)

# 8. Kebutuhan Non Fungsional

NFR-001 Website harus responsif.

NFR-002 Website harus mobile-first.

NFR-003 Website harus menggunakan HTTPS.

NFR-004 Password harus disimpan menggunakan hashing.

NFR-005 Login menggunakan password dan TOTP.

NFR-006 Sistem harus memiliki rate limiting login.

NFR-007 Sistem harus memiliki proteksi CSRF.

NFR-008 Sistem harus memiliki validasi input.

NFR-009 Sistem harus memiliki audit log.

NFR-010 Sistem harus mendukung backup database.

NFR-011 Website harus dapat berjalan pada hosting shared.

NFR-012 Website harus kompatibel dengan browser modern.

NFR-013 Website harus mendukung SEO dasar.

NFR-014 Website harus memiliki performa yang baik pada jaringan seluler.

NFR-015 Website harus menggunakan media optimization.

---

# 9. Aturan Bisnis

BR-001 Hanya terdapat satu akun admin.

BR-002 Admin tidak dapat membuat admin baru.

BR-003 Admin tidak dapat menghapus akun admin utama.

BR-004 Guest tidak memerlukan akun.

BR-005 Konten dapat dipublikasikan atau diarsipkan.

BR-006 Audit log wajib disimpan.

BR-007 Audit log tidak dapat dihapus manual.

BR-008 Seluruh konten dikelola melalui dashboard.

BR-009 Website harus tetap dapat berjalan meskipun belum memiliki konten.

BR-010 Sistem harus dapat digunakan ulang untuk desa lain tanpa perubahan source code utama.

---

# 10. Strategi Deployment

Tahap awal:

* Cloudflare
* Hosting ekonomis
* Domain sementara atau pribadi

Tahap adopsi desa:

* Domain resmi desa
* Hosting yang lebih besar
* Migrasi data
* Pelatihan admin
* Serah terima dokumentasi
* Serah terima source code

---

# 11. Status Kepemilikan

Pada tahap pengembangan dan KKN:

Pemilik sistem adalah pengembang.

Apabila desa memutuskan mengadopsi sistem:

* Dilakukan serah terima resmi.
* Dilakukan migrasi domain dan hosting.
* Dilakukan pelatihan admin.
* Dilakukan penyerahan dokumentasi.
