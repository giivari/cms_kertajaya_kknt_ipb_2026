# 1. Perubahan Kebijakan Watermark

Village Website CMS menerapkan dua jenis watermark:

1. Watermark tak terlihat.
2. Watermark terlihat.

Watermark tak terlihat wajib diterapkan secara otomatis pada seluruh media yang masuk ke dalam sistem.

Watermark terlihat merupakan fitur tambahan yang dapat diaktifkan atau dinonaktifkan sesuai konfigurasi administrator.

---

# 2. Watermark Tak Terlihat

## 2.1 Definisi

Watermark tak terlihat merupakan informasi identifikasi yang ditanam pada file media tanpa menghasilkan tanda visual yang mengganggu tampilan normal media.

Watermark ini digunakan untuk:

1. Mengidentifikasi sumber media.
2. Menghubungkan media dengan instalasi website.
3. Mengidentifikasi file meskipun nama file telah berubah.
4. Membantu pemeriksaan penggunaan ulang media.
5. Menyediakan bukti teknis bahwa media pernah diproses melalui sistem.
6. Melengkapi metadata provenance dan digital fingerprint.

---

## 2.2 Sifat Wajib

Watermark tak terlihat:

* Aktif secara default.
* Tidak dapat dinonaktifkan oleh administrator.
* Tidak memiliki pengaturan pengecualian per media.
* Diterapkan pada seluruh media yang diunggah.
* Diterapkan sebelum media tersedia untuk digunakan.
* Diterapkan kembali apabila media publik dibuat ulang.
* Berlaku pada media yang digunakan maupun yang belum digunakan.
* Berlaku pada media yang ditampilkan secara publik maupun disimpan secara privat.

Administrator tidak memiliki tombol untuk menonaktifkan atau melewati proses watermark tak terlihat.

---

# 3. Cakupan Media

Watermark tak terlihat wajib diterapkan pada seluruh tipe media yang didukung sistem.

## 3.1 Gambar

Mencakup:

* JPG.
* JPEG.
* PNG.
* WebP.
* Thumbnail.
* Gambar hasil optimasi.
* Gambar galeri.
* Gambar berita.
* Gambar lokasi.
* Gambar Page Builder.
* Banner.
* Logo yang diunggah ke Media Library.
* Gambar dekoratif.
* Poster dan infografis.

## 3.2 Dokumen

Mencakup:

* PDF.
* PDF hasil pemrosesan ulang.
* Dokumen publik.
* Formulir.
* Lampiran informasi.

## 3.3 Pengembangan Format Berikutnya

Apabila sistem mendukung media baru, seperti:

* Video.
* Audio.
* SVG.
* Dokumen perkantoran.

media tersebut juga wajib melewati mekanisme identifikasi tak terlihat yang sesuai dengan formatnya.

Tidak semua format menggunakan algoritma watermark yang sama. Sistem harus menggunakan pemroses khusus berdasarkan jenis media.

# 4. Identitas Watermark

Setiap media memiliki payload identifikasi yang unik.

Payload minimal mencakup:

* ID instalasi.
* ID media.
* Versi watermark.
* Waktu pemrosesan.
* Identifier unik.
* Checksum atau hash referensi.

Contoh struktur logis:

```json id="a7304u"
{
  "installation_id": "VWCM-KERTAJAYA-001",
  "media_id": 152,
  "watermark_version": "1.0",
  "watermark_identifier": "26f57d80-5c55-4a41-a59c-a1c6da5df513",
  "processed_at": "2026-07-15T10:30:00+07:00"
}
```

Payload sebenarnya tidak harus disimpan sebagai teks terbuka dalam file. Sistem dapat mengubahnya menjadi bentuk biner atau kode yang sesuai dengan algoritma watermark.

---

# 5. Identitas Instalasi

Setiap instalasi Village Website CMS wajib memiliki identifier unik.

Identifier tersebut disebut:

```text id="zrn93v"
installation_id
```

Contoh:

```text id="s1fscu"
VWCM-KERTAJAYA-001
```

Identifier instalasi:

* Dibuat ketika sistem pertama kali dikonfigurasi.
* Tidak dapat diubah melalui dashboard biasa.
* Tidak bergantung pada domain.
* Tetap sama ketika website dipindahkan ke domain atau server lain.
* Digunakan sebagai bagian dari identitas watermark.
* Disimpan secara aman dalam konfigurasi sistem.

Dengan demikian, media tetap dapat diidentifikasi meskipun website telah berganti:

* Domain.
* Hosting.
* Nama desa.
* Logo.
* Pengelola.

# 6. Strategi Perlindungan Berlapis

Watermark tak terlihat tidak menggunakan satu mekanisme tunggal.

Sistem menerapkan tiga lapisan identifikasi.

## 6.1 Lapisan Pertama — Watermark dalam Isi Media

Informasi identifikasi ditanam ke dalam:

* Pixel gambar.
* Struktur atau objek dokumen.
* Data media lain sesuai format.

Watermark dirancang agar tidak terlihat pada penggunaan normal.

## 6.2 Lapisan Kedua — Metadata Provenance

Sistem menambahkan metadata yang menjelaskan:

* Sumber.
* Waktu pemrosesan.
* Identifier media.
* Identifier instalasi.
* Riwayat proses.
* Checksum.

Apabila memungkinkan, implementasi dapat mengikuti atau dipersiapkan agar kompatibel dengan standar provenance seperti C2PA.

## 6.3 Lapisan Ketiga — Digital Fingerprint

Sistem menghasilkan sidik digital dari media.

Fingerprint dapat berupa:

* Cryptographic hash.
* Perceptual hash.
* Checksum file.
* Identitas turunan media.

Cryptographic hash digunakan untuk memeriksa file yang identik.

Perceptual hash dapat digunakan untuk membantu menemukan versi media yang telah mengalami perubahan ringan.

# 8. Pemrosesan File Asli

File yang pertama kali diunggah tidak langsung disediakan kepada frontend.

Sistem membuat:

1. Salinan unggahan awal untuk backup internal, apabila diperlukan.
2. Master media yang telah diberi watermark tak terlihat.
3. Versi teroptimasi.
4. Thumbnail.
5. Versi publik.
6. Versi dengan watermark terlihat jika diaktifkan.

Semua versi yang dapat dipakai atau diekspor dari sistem wajib mengandung watermark tak terlihat.

File unggahan mentah yang belum memiliki watermark:

* Tidak boleh tersedia pada URL publik.
* Tidak boleh digunakan dalam konten.
* Tidak boleh diunduh melalui dashboard biasa.
* Tidak boleh dipindahkan ke penyimpanan publik.
* Hanya boleh dipertahankan sebagai backup teknis yang sangat terbatas apabila memang diperlukan.

# 9. Watermark Terlihat

Watermark terlihat tetap bersifat opsional.

Administrator dapat mengatur:

* Aktif atau tidak aktif.
* Logo.
* Teks.
* Posisi.
* Transparansi.
* Ukuran.
* Margin.
* Penggunaan berdasarkan konteks media.

Watermark terlihat dapat dikecualikan untuk media tertentu.

Pengecualian watermark terlihat tidak memengaruhi watermark tak terlihat.

# 10. Verifikasi Watermark

Sistem menyediakan proses verifikasi internal.

Administrator dapat:

1. Memilih media.
2. Menjalankan pemeriksaan watermark.
3. Melihat hasil deteksi.
4. Melihat identifier yang ditemukan.
5. Membandingkan dengan data media.
6. Melihat checksum dan fingerprint.
7. Melihat riwayat pemrosesan.

Hasil verifikasi:

* `verified`
* `partially_verified`
* `not_detected`
* `invalid`
* `unsupported`

Verifikasi tidak boleh mengubah file media.

# 11. Pengunduhan Media oleh Administrator

Media yang diunduh dari dashboard tetap harus mengandung watermark tak terlihat.

Pilihan pengunduhan:

* Versi publik.
* Versi teroptimasi.
* Versi dengan watermark terlihat.
* Master terlindungi.

File mentah tanpa watermark tidak disediakan melalui dashboard.

Akses terhadap file mentah, apabila dipertahankan, hanya dapat dilakukan melalui prosedur teknis khusus oleh pemilik sistem.

# 19. Batasan Teknis

1. Algoritma watermark gambar tidak dapat langsung digunakan pada PDF, video, atau audio.
2. Setiap format memerlukan pemroses khusus.
3. Ketahanan watermark bergantung pada algoritma yang digunakan.
4. Rekonstruksi media berat dapat menghilangkan watermark.
5. Beberapa algoritma watermark membutuhkan lisensi atau layanan eksternal.
6. Implementasi mandiri harus diuji terhadap kompresi, crop, resize, dan perubahan format.
7. Metadata provenance dapat hilang apabila platform menghapus metadata.
8. Fingerprint tidak menggantikan watermark, tetapi digunakan sebagai lapisan pendukung.
9. Sistem harus menyimpan versi algoritma agar media lama tetap dapat diverifikasi.
10. Key atau secret watermark harus dikelola di luar source code.

# 21. Kesimpulan

Village Website CMS menerapkan watermark tak terlihat sebagai persyaratan wajib dan tidak dapat dinonaktifkan.

Arsitektur perlindungan media menjadi:

```text id="l9tt10"
Media Diunggah
      ↓
Identitas Unik
      ↓
Checksum dan Fingerprint
      ↓
Watermark Tak Terlihat
      ↓
Metadata Provenance
      ↓
Verifikasi
      ↓
Versi Turunan Terlindungi
      ↓
Watermark Terlihat Opsional
      ↓
Publikasi
```

Dengan kebijakan tersebut, seluruh media yang digunakan sistem memiliki identitas teknis yang dapat ditelusuri tanpa bergantung pada watermark visual.
