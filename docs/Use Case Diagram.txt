# 1. Pendahuluan

## 1.1 Tujuan Dokumen

Dokumen Use Case Specification digunakan untuk menjelaskan interaksi antara aktor dan sistem pada Village Website CMS.

Dokumen ini bertujuan untuk:

* Mendefinisikan fungsi sistem secara rinci.
* Menjadi dasar penyusunan Use Case Diagram.
* Menjadi dasar penyusunan Activity Diagram.
* Menjadi dasar perancangan database.
* Menjadi dasar implementasi sistem.

---

## 1.2 Ruang Lingkup

Dokumen ini mencakup seluruh proses bisnis yang terjadi pada Village Website CMS, baik pada sisi pengunjung website (Guest) maupun administrator sistem (Admin).

---

# 2. Aktor Sistem

## 2.1 Guest

Guest merupakan pengunjung website yang tidak memerlukan akun untuk mengakses informasi publik.

### Hak Akses

* Mengakses website publik.
* Membaca halaman informasi.
* Membaca berita.
* Melihat galeri.
* Mengunduh dokumen publik.
* Menggunakan fitur pencarian.
* Melihat peta lokasi.
* Mengirim pesan melalui narahubung.

---

## 2.2 Admin

Admin merupakan pengelola website yang memiliki akses penuh terhadap dashboard administrasi.

### Hak Akses

* Login dan logout.
* Mengelola halaman.
* Mengelola berita.
* Mengelola galeri.
* Mengelola dokumen.
* Mengelola media library.
* Mengelola menu.
* Mengelola pengaturan website.
* Mengelola lokasi peta.
* Mengelola pesan narahubung.
* Melihat audit log.

# 4. Spesifikasi Use Case

---

## UC-A01 – Login

### Deskripsi

Use case ini memungkinkan administrator mengakses dashboard sistem.

### Aktor

Admin

### Prasyarat

1. Akun administrator telah tersedia.
2. Administrator mengetahui kredensial login.
3. Administrator memiliki akses terhadap perangkat autentikasi TOTP.

### Alur Utama

1. Administrator membuka halaman login.
2. Administrator memasukkan username.
3. Administrator memasukkan password.
4. Sistem memverifikasi kredensial.
5. Sistem meminta kode autentikasi TOTP.
6. Administrator memasukkan kode TOTP.
7. Sistem memverifikasi kode.
8. Sistem menampilkan dashboard.

### Alur Alternatif

#### A1 – Password Tidak Valid

1. Sistem menolak proses login.
2. Sistem menampilkan pesan kesalahan.
3. Sistem mencatat aktivitas ke audit log.

#### A2 – Kode TOTP Tidak Valid

1. Sistem menolak proses login.
2. Sistem meminta kode TOTP kembali.
3. Sistem mencatat aktivitas ke audit log.

### Pasca Kondisi

Administrator berhasil masuk ke dashboard.
