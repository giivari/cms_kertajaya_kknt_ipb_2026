# SECURITY SPECIFICATION DOCUMENT

## Village Website CMS

**Versi Dokumen:** 1.0
**Status:** Approved Draft
**Jenis Dokumen:** Security Architecture Specification
**Berlaku Untuk:** Seluruh Implementasi Village Website CMS
**Tanggal:** Juli 2026

---

# 1. Pendahuluan

## 1.1 Tujuan

Dokumen ini mendefinisikan standar keamanan yang diterapkan pada Village Website CMS.

Tujuan utama:

* Melindungi dashboard admin.
* Melindungi data website.
* Melindungi media dan dokumen.
* Mengurangi risiko serangan umum.
* Menyediakan standar keamanan yang realistis untuk website desa.

---

# 2. Filosofi Keamanan

Village Website CMS menggunakan pendekatan:

```text
Secure by Default
```

Artinya:

* Fitur keamanan aktif secara bawaan.
* Administrator tidak perlu konfigurasi rumit.
* Sistem tetap aman meskipun operator non-teknis.

---

# 3. Model Akses

## Guest

Hak akses:

* Read Only

Dapat:

* melihat halaman
* melihat berita
* melihat galeri
* mengunduh dokumen publik
* mengirim pesan

Tidak dapat:

* mengubah data
* mengakses dashboard

---

## Admin

Hak akses:

* Full Access

Jumlah:

```text
1 akun admin
```

Tidak mendukung:

* multi admin
* role management
* permission hierarchy

---

# 4. Dashboard Protection

## URL Admin Terpisah

Dashboard tidak menggunakan:

```text
/admin
```

secara langsung.

Contoh:

```text
/desa-dashboard
```

atau:

```text
/portal-kelola
```

---

## Authentication Layer

Login wajib melalui:

```text
Username
Password
CAPTCHA
TOTP
```

---

## Session Security

Session:

* HttpOnly
* Secure Cookie
* SameSite Strict

---

## Session Timeout

Idle timeout:

```text
30 menit
```

Absolute timeout:

```text
8 jam
```

# 25. Kesimpulan

Village Website CMS menggunakan pendekatan keamanan berlapis:

```text
Cloudflare
↓
HTTPS
↓
Authentication
↓
TOTP
↓
Rate Limiting
↓
Application Security
↓
Media Protection
↓
Audit Logging
↓
Backup
```

Pendekatan ini memberikan tingkat keamanan yang tinggi untuk kebutuhan website desa tanpa menambah kompleksitas berlebihan bagi operator.
